# 心猿意马的羊｜交易复盘：个人投资交易学习旗舰产品蓝图

> 版本：2.1 ｜修订日期：2026-08-17 ｜首期节奏：6 周封闭建设、45 天公开验证、一年演进  
> 产品边界：投资交易学习与市场研究记录；不荐股、不承诺收益、不代客操作、不公开个人持仓与买卖动作、不提供个性化投资建议。

## 0. 执行摘要

### 首期方案

- **个人署名**：心猿意马的羊｜交易复盘。
- **一句话定位**：持续公开有事实、有判断、有边界、有后续校准的市场复盘，让交易爱好者通过长期案例共同学习。
- **首期核心产品**：内容型网站 + 每日复盘 + 每周复盘 + 日期归档 + 配套海报。
- **首期核心价值**：不是先教别人填写方法，而是先证明主理人能够长期、准时、透明地完成自己的复盘。
- **首页核心动作**：阅读最新复盘、浏览历史归档。
- **六周验证对象**：验证个人内容生产系统能否持续运行，不做收费，不验证读者填写，不伪造用户反馈。
- **公开后的北极星指标**：每周回访读者趋势。
- **参考模型**：以 Monevator 的平视关系、长期归档和支持型会员哲学为首要产品参考；以 Net Interest 的付费研究与档案产品化作为后续商业参考；Dan Koe Letters 与 Eden 只承担视觉参考。

### 为什么不是继续改造“我的投资笔记”

旧项目已经积累了数据读取、飞书同步和海报能力，但首页把每日简报、老师观点和交易复盘连续平铺，仍然像把个人材料放到网上，没有形成稳定、可追踪的内容产品。

新产品不再用“教读者填表”解决商业感，而是先建立一条可信的公开记录：

1. 每个 A 股交易日当晚发布一篇精编日复盘。
2. 每周发布一篇独立的高周期复盘。
3. 每篇内容明确区分事实、解释、判断和保留条件。
4. 原判断保留，后续结果以追加校准的方式记录。
5. 海报承担传播，网站沉淀完整文章与历史档案。

### 最关键的范围决定

1. 首期只验证一个旗舰价值：**“心猿意马的羊”能否形成稳定、准时、可校准的公开复盘档案。**
2. 每日简报降为事实输入，不占据网站主栏目；“老师观点”不进入新网站。
3. 正式栏目只有每日复盘和每周复盘；方法、工具、研究看板暂不独立成栏目。
4. 六周只做封闭预览和个人运行测试；公开部署、域名、统计及外部发布必须重新授权。
5. ERP、估值和相对比价只作为研究证据，不包装成买卖信号。
6. 内容会员是后续第一商业假设，研究辅助工具或 Agent 在真实需求成立后再做。

## 1. 产品定义

### 1.1 服务谁

核心读者是愿意长期观察市场、喜欢交易、希望通过真实复盘案例共同学习的人。他们不必认同主理人的每个判断，也不需要采用相同的交易方式；他们回来，是为了看到：

- 当天发生了什么，以及哪些信息真正重要。
- 主理人如何从盘面事实走到结构判断。
- 判断成立需要哪些条件，什么会证明它不成立。
- 旧判断后来怎样，错误如何被记录和修正。

优先服务三类读者：

1. **市场观察者**：每天接触大量信息，需要一篇有层次的盘后整理。
2. **交易爱好者**：重视盘面、量价、风格和外围映射，希望比较不同判断过程。
3. **长期同行者**：更关心判断怎样形成和修正，而不是只看某一天是否猜对。

暂不服务：只要即时荐股、要求收益承诺、寻求代客操作、希望查看个人仓位或要求个性化买卖建议的人。

### 1.2 读者为什么来

- **首次访问**：快速理解作者是谁、如何复盘，以及最新市场判断的依据和边界。
- **持续回访**：阅读新的日复盘、周复盘，并查看旧判断的后续校准。
- **长期信任**：网站保留原判断、数据日期、来源、保留条件和修正记录，不删除错误、不只展示命中。

### 1.3 价值主张与单一承诺

**价值主张**：把每天的市场观察变成有时间顺序、有证据边界、有后续校准的公开内容资产。

**单一承诺**：每次来到“心猿意马的羊｜交易复盘”，读者都能看到一份不隐藏不确定性、以后还会回来检验的真实市场复盘。

### 1.4 与常见内容的差异

| 类型 | 主要交付 | 常见缺口 | 本产品的区别 |
|---|---|---|---|
| 个人日记 | 作者当天的想法 | 更新不稳定，缺少公开规则 | 固定频率、固定元数据、日期归档和后续校准 |
| 行情资讯 | 新闻、涨跌和热点 | 信息多，判断链条弱 | 只保留与结构判断有关的事实，并解释其含义 |
| 荐股账号 | 标的和方向 | 权威依赖、跟单与合规风险 | 不公开买卖动作，重点呈现事实、判断和边界 |
| 数据终端 | 指标和图表 | 数据不等于理解 | 每个数据必须回答它支持、限制或否定什么 |
| 教学内容 | 方法和知识点 | 缺少主理人长期实践证据 | 先持续公开自己的复盘，再从真实积累中提炼方法 |

### 1.5 产品参考原则

[Monevator](https://monevator.com/) 是首要产品关系参考，不是首期视觉模板。具体吸收四项原则：

1. **个人投资者写给个人投资者**：保持独立、平视、有分歧空间的作者声音，不包装成机构或老师。
2. **免费内容本身完整**：公开文章不能被故意截断，先让日复盘、周复盘和校准档案建立真实价值。
3. **历史归档是产品**：旧内容不只是日期列表，还要能帮助读者发现代表文章、连续判断和后续校准。
4. **会员支持长期创作**：未来会员卖持续关系、整理价值和独立内容，不卖更准确的信号或隐藏的买卖答案。

[Net Interest](https://www.netinterest.co/) 只作为后续付费研究结构参考：当周复盘和历史档案已经形成稳定回访后，再考虑更深的会员研究、专题档案或订阅者信件。首期不实施付费墙、会员账户或文章截断。

### 2.2 “自用博客感”的原因

1. **名称和首屏只有记录视角**：“我的投资笔记”说明作者在做什么，却没有建立可持续追踪的内容承诺。
2. **首页没有内容主线**：每日简报、老师观点、交易复盘连续平铺，读者不知道先看什么、为什么回来。
3. **身份不一致**：“共同学习”与“老师观点”“操作建议”并存，容易形成权威依赖。
4. **内容结构依赖卡片堆叠**：信息层级主要靠边框和颜色，而不是编辑顺序和阅读节奏。
5. **缺少内容产品动作**：没有明确的“阅读最新复盘—进入历史归档—查看后续校准”路径。
6. **缺少统一信任协议**：来源、数据截止、主观判断、验证状态和修正记录没有统一展示。
7. **静态内容与运行时 JSON 双轨**：HTML 内嵌内容、脚本 fallback 和 JSON 都可能成为展示源，容易不一致。
8. **数据已明显陈旧**：审计日为 2026-08-16；每日简报停在 2026-07-02，老师观点和交易复盘停在 2026-07-03，ERP/相对比价停在 2026-08-07，恒指 ERP 停在 2026-07-31。旧站没有在首屏明确暴露这种陈旧状态。

### 2.3 文档与实际行为冲突

- AUTOMATION_SETUP.md 仍称老师观点是当前过渡来源，但 GitHub Actions 已变成飞书复盘文件夹优先、老师观点仅为失败兜底。
- DAILY_BRIEF_SETUP.md 指导设置 window.DAILY_BRIEF_URL，当前 index.html 没有配置；实际默认读取本地 JSON。
- 双海报流程要求 lark-cli 不低于 1.0.84，现有 GitHub Actions 安装 1.0.56。
- ERP 归档包含非严格 JSON 的 NaN；周摘要脚本会先转换为 null 才解析。任何新数据层必须在边界处规范化。

### 2.4 不带入新产品的内容

- “老师观点”栏目及其身份标签。
- 将综合新闻简报作为首页第一核心内容。
- 模拟搜索、订阅、标签云等没有真实功能的装饰。
- 由脚本直接覆盖正式主观判断的发布方式。
- 首页一次展示完整长复盘和全部数据表。
- 把 ERP、相对比价或板块强弱包装成无条件交易建议。
- 在首期要求读者填写、练习或提交复盘。

## 3. 个人身份与表达系统

### 3.1 首期署名

- **网站署名**：心猿意马的羊｜交易复盘。
- **海报署名**：心猿意马的羊 · 每日收盘复盘；周内容对应改为“每周市场复盘”。
- **身份说明**：一个持续记录市场、公开判断边界并回看错误的交易学习者。
- **命名策略**：六周封闭预览不创建独立品牌名；正式公开前再检查网名、域名和平台账号的一致性。

### 3.2 表达原则

- 先事实，后解释，再给当前判断和保留条件。
- 使用平视口吻，不以老师、导师、研究院或机构身份包装。
- 承认未知，避免把短期推演写成确定性结果。
- 不因结果难看删除原判断，校准只能追加。
- 不把个人体感伪装成市场事实，不虚构资金来源和因果关系。

### 3.3 推荐与禁用表达

- **推荐关键词**：事实、结构、当前判断、边界、观察、校准、误差、暂未确认。
- **禁用表达**：稳赚、必涨、抄底、带你赚钱、老师带盘、闭眼买、精准逃顶、内部消息、确定性机会。
- **安全落款**：固定免责声明唯一文本见 `docs/content/site-copy.md` 第 7 节，全文不得改写。

## 4. 内部编辑与质量协议

### 4.1 内部完整性检查

原蓝图中的“五格复盘法”不再作为对外品牌、页面、教程或读者工具。首期仅把其核心思想降为内部质检问题：

1. 是否写清可以核验的市场事实和数据日期。
2. 是否解释这些事实构成了什么市场结构。
3. 是否明确当前判断，而不是只复述涨跌。
4. 是否写出保留条件和可能推翻判断的证据。
5. 是否在后续日期追加结果、偏差和规则修正。

这五项只用于检查文章完整性，不在首页宣传，不提供空白表格，不作为用户转化指标。未来若稳定内容积累证明其确有价值，再从真实案例中重新提炼公开方法。

### 4.2 每日精编文章结构

一篇公开日复盘按下列顺序编辑：

1. **标题**：两段式题眼，描述已发生的事实和当前判断。
2. **导语**：两到三句交代当日盘面、主要矛盾与保留条件。
3. **关键事实**：成交、涨跌广度、中位数、日内节奏、代表指数或风格；每个数字说明含义。页面上默认折叠。
4. **当前判断**：明确判断及其证据，不写买卖动作。
5. **边界与观察**：一到三条可检验条件，说明什么会支持或否定判断。
6. **收盘点评**：把量价、结构、趋势边界和外围影响串成完整因果链。
   （2026-09-24 起删除原「结构解释」——与「收盘点评」内容重复。）
8. **个人感悟**：一句真实、克制、不重复点评的个人观察。
9. **海报摘要**：嵌入已核验海报，作为文章结论页。
10. **来源与免责声明**：列出数据截止时间、来源和安全边界。
11. **校准记录**：后续按日期追加，不覆盖以上原判断。

公开文章是从飞书确认终稿编辑出的精简长文，不完整展示飞书原始笔记、截图或所有过程内容。

### 4.3 每周复盘结构

周复盘是独立的高周期判断，不负责逐篇汇总当周日复盘。建议结构：

1. 本周题眼与核心判断。
2. 指数趋势、量价与风险偏好。
3. 风格和板块结构。
4. ERP、PE、波动率和成交集中度等估值证据。
5. 港股、美股、黄金等外围映射。
6. 下周需要继续观察的条件。
7. 个人感悟、海报摘要、来源与免责声明。
8. 后续校准记录。

### 4.4 发布质量门槛

每篇进入网站预览前必须满足：

- 事实、判断、边界三者可被读者区分。
- 数据有来源和截止日期；过期数据按规则标记。
- 今日判断、收盘点评和感悟已由用户明确确认。
- 不包含仓位、账户金额、具体买卖动作或个性化建议。
- 海报中文字体、换行、关键数字、颜色语义、底部感悟和免责声明通过核验。
- 原判断区不可被后续校准覆盖。

## 5. 产品与信息架构

### 5.1 导航与页面职责

| 页面 | 核心任务 | 首期关键内容 | 主要动作 |
|---|---|---|---|
| 首页 | 让读者 30 秒理解作者与内容承诺 | 作者身份、最新日复盘、最新周复盘、最近更新、归档入口、数据说明 | 阅读最新复盘 |
| 每日复盘 | 建立交易日持续更新的内容主线 | 按日期倒序的日复盘列表、摘要、判断状态、数据日期 | 打开当天文章 |
| 每周复盘 | 展示独立的高周期市场判断 | 按周倒序的周复盘列表、估值日期、观察条件 | 阅读最新周报 |
| 归档 | 把长期内容本身做成产品 | 最新更新、精选入口、年/月索引、内容类型、连续判断和校准状态 | 浏览历史与校准 |
| 关于 | 建立平视信任和边界 | 作者说明、内容原则、来源政策、修正政策、免责声明 | 了解写作规则 |

桌面导航固定为：首页 / 每日复盘 / 每周复盘 / 归档 / 关于。移动端只显示署名、菜单按钮和“最新复盘”入口；展开菜单后显示完整导航，禁止横向滚动。

### 5.2 读者路径

~~~text
小红书海报或直接访问
  → 首页理解“心猿意马的羊｜交易复盘”
  → 阅读最新日复盘或周复盘
  → 通过日期归档查看过去判断
  → 阅读后续校准
  → 在下一个交易日或下一周回来查看更新
~~~

首期不要求登录、不收集邮箱、不提供在线填写、不建立社区。公开阶段的渠道关注只作为次级动作，不抢占网站主阅读路径。

### 5.4 归档产品化要求

归档页不照搬 Monevator 的旧视觉，但吸收其“长历史可重新发现”的逻辑。首期必须做到：

- **最新更新**：按发布时间展示最近日复盘、周复盘和校准追加，不让校准埋在旧文章里。
- **精选复盘**：由主理人手工选择代表性文章；选择标准是判断链条和校准价值，不是结果最好。
- **年月索引**：按年份和月份浏览，日复盘与周复盘使用同一内容集合生成。
- **状态识别**：列表直接显示待验证、部分支持、被否定、已校准。
- **连续阅读**：文章页提供上一篇、下一篇，以及同周或相关校准入口。
- **稳定链接**：文章 URL 发布后不因改标题变化；校准更新沿用原文章 URL。

首期不做全文搜索、复杂标签、排行榜、推荐算法或用户收藏。数据量证明年月索引不够用后，再决定是否增加搜索。

### 5.5 首期必须做与明确不做

**必须做**：作者身份、首页、每日复盘、每周复盘、日期归档、文章详情、校准追加、海报嵌入、数据状态、移动端、上一篇/下一篇、关于与免责声明。

**不做**：方法教学页、读者填写工具、账号系统、社区 feed、实时行情终端、付费墙、个性化推荐、ERP Agent、原生 App、复杂搜索、评论系统、多作者后台、广告和联盟推荐。

## 6. 内容栏目与生产系统

### 6.1 两个正式栏目

| 栏目 | 读者价值 | 频率与时限 | 内容来源 | 人工边界 | 调整条件 |
|---|---|---|---|---|---|
| 每日复盘 | 看见当日事实怎样形成当前判断 | 每个 A 股交易日一篇，当日 23:59 前进入网站预览 | 飞书当日复盘、正式行情和已确认三段文字 | 本人确认判断、点评与感悟；网站公开版手动编辑 | 连续两周无法达到 90% 当晚完成率时，先削减渠道加工和页面迭代，不削减复盘本身 |
| 每周复盘 | 获得独立的高周期市场判断 | 每周一篇，周日 23:59 前进入网站预览 | 飞书周复盘、正式估值与风险数据 | 本人解释趋势、估值和观察条件；数据草稿不能替代判断 | 连续两周超过 3 小时，先压缩重复数据和图表，不改成日报汇总 |

### 6.2 首发内容组合

- 从历史材料中精选并重编 8—12 篇日复盘。
- 从历史材料中精选并重编 2—3 篇周复盘。
- 选择标准不是结果是否正确，而是事实、判断、边界和后续校准是否具有代表性。
- 建设期间的新内容从第 1 周开始持续积累，网站完成后补录，不能等页面做完才开始生产。

### 6.3 手工生产链路

1. 在飞书复盘文件夹中找到当日或当周文档。
2. 读取并区分事实记录、用户原判断、图片、提示文字和缺失内容。
3. 分析盘面并形成今日/本周判断草案。
4. 依次共同打磨今日判断、收盘点评和感悟。
5. 三段全部确认后，一次性回填飞书，不覆盖其他记录。
6. 从确认内容与代表数字生成海报，并完成 1080×2000 渲染核验。
7. 将飞书确认终稿编辑成网站公开版 MDX；精简重复事实，但不得改变判断含义。
8. 在本地或封闭预览检查元数据、正文、海报、来源、上一篇/下一篇和移动端。
9. 当日 23:59 前把日复盘放入网站预览。
10. 到校准日期后追加结果、偏差原因和规则调整；原判断保持不变。

### 6.4 稳定运营周排期（约 20 小时）

| 工作 | 每周预算 |
|---|---:|
| 5 篇日复盘端到端完成 | 8 小时 |
| 1 篇独立周复盘 | 3 小时 |
| 历史判断校准与归档 | 2 小时 |
| 小红书海报与发布准备 | 2.5 小时 |
| 网站内容检查与小修 | 2 小时 |
| 数据异常、补录和机动 | 2.5 小时 |
| **合计** | **20 小时** |

若连续两周超过 20 小时，优先减少跨渠道改写、视觉变化和网站小功能；每日/每周复盘、来源核验和原判断保留不能被削减。

## 7. 体验与视觉原则

### 7.1 参考站分工（2026-08-17）

- **首要产品与商业哲学参考：[Monevator](https://monevator.com/)**。借鉴个人投资者的平视身份、完整免费内容、长期归档、独立编辑和支持型会员逻辑；不照搬其较老的页面视觉，也不在首期实现会员、评论、广告或联盟体系。
- **未来付费研究参考：[Net Interest](https://www.netinterest.co/)**。借鉴垂直主题、稳定周更、可搜索历史档案和免费到付费的内容分层；只有回访和主动付费需求成立后才采用，不在首期截断文章。
- **编辑排版参考：[Dan Koe Letters](https://letters.thedankoe.com/)**。桌面端用居中大版心、单一主推、热门横排、最新列表和侧栏形成编辑层级；移动端将内容压为单列，并把热门横排让位给最新文章。可借鉴“一个主推 + 编辑列表”，不照搬其移动端横向分类导航裁切。
- **复杂信息视觉参考：[Eden](https://eden.so/)**。桌面端用巨大价值承诺和连续编号段落建立商业感，移动端保留品牌、主动作、价值承诺和纵向收益点。可借鉴模块纪律，不照搬其超长页面和演示图横向裁切。

产品逻辑的优先级高于视觉相似度。如果视觉参考与 Monevator 式长期阅读、归档发现或平视关系冲突，以产品逻辑为准。

### 7.2 设计系统原则

- **背景**：#0A0B0B；主要面板 #121414；悬浮层 #191C1B。
- **文字**：主文字 #F3F1EA；次级 #A6AAA6；弱信息 #737873。
- **强调**：鼠尾草绿 #A8C7A5 表示已校准或可继续阅读；珊瑚红 #D9837C 表示风险或被否定。行情涨跌另配图标和文字，不能只靠颜色。
- **字体**：中文界面使用现代无衬线；长复盘正文可用克制宋体或衬线；数字使用等宽或表格数字。
- **版心**：桌面最大 1240px；正文阅读宽 720—760px；首页模块垂直间距 96—128px。
- **密度**：首屏只出现一个 H1、两句解释、两个阅读动作和四条信任协议。
- **边框**：1px 弱边框、8—12px 圆角；避免旧站的多色渐变、大面积彩色光斑和每块内容都卡片化。
- **动效**：150—220ms 淡入或位移；尊重 prefers-reduced-motion；不使用行情闪烁和滚动数字制造紧迫感。

### 7.3 响应式优先级

- 390px 移动宽度采用 20px 页面边距，正文不小于 16px，任何内容不得造成页面横向滚动。
- 首页移动首屏顺序：署名与最新复盘入口 → 内容承诺 → 最新日复盘 → 最新周复盘 → 最近更新 → 归档。
- 数据表在移动端转为“指标—数值—含义”纵向行；先显示含义，再允许展开详细值。
- 导航使用菜单按钮，不保留可横向滚动的多项导航。
- 海报保持完整比例，可点开查看原图；不能为了适配正文裁切底部内容。

### 7.4 建立信任而非制造权威

每篇复盘头部固定显示：作者、内容类型、发布日期、数据截止、来源数量、判断状态和最近校准日期。正文保留原判断，校准只追加不覆盖；页面底部显示来源政策和免责声明。

## 8. 技术与数据蓝图

### 8.1 首期技术决定

- **站点**：使用独立 Astro 静态站，TypeScript + Markdown/MDX 内容集合；`investment-portal` 是唯一主项目。
- **思考母稿**：飞书中的确认终稿是原始记录和主观判断的唯一母稿。
- **网站稿**：Git 仓库内 Markdown/MDX 是对外编辑版；不得反向覆盖飞书。发生表述冲突时，以飞书已确认内容为准重新编辑。
- **托管**：六周只做本地或封闭预览。通过验收并重新获批后建立预览托管；正式域名与公开发布再次单独确认。
- **数据层**：首期不引入数据库和 CMS；结构化行情与元数据使用标准 frontmatter。
- **样式**：CSS design tokens + 少量组件；不引入大而全 UI 框架。
- **统计**：六周不接正式分析工具。公开阶段获批后，只记录页面、来源渠道、回访、归档进入和文章导航等最小事件。

### 8.2 核心内容模型

~~~yaml
id: 2026-08-16-daily
author: 心猿意马的羊
type: daily | weekly
status: draft | confirmed | preview | public
date: 2026-08-16
published_at: 2026-08-16T22:30:00+08:00
data_as_of: 2026-08-16
title: 已发生的事实 / 当前判断
summary: 两到三句公开摘要
sources:
  - label: 数据源名称
    url: 可选
sections:
  facts: []
  structure: ""
  judgment: ""
  boundary: []
  commentary: ""
  feeling: ""
poster:
  src: /posters/20260816.png
  alt: 2026-08-16 每日复盘海报
calibrations:
  - date: 2026-08-20
    outcome: supported | partial | falsified | pending
    notes: ""
    error_tags: []
    rule_change: ""
disclaimer: personal_market_review
~~~

实现约束：

- type 首期只能是 daily 或 weekly。
- calibrations 是只追加数组，既有记录不可由后续发布流程删除。
- data_as_of、sources、sections.judgment、sections.boundary 和 disclaimer 为发布必填。
- poster 在文章草稿阶段可为空，进入 preview 前必须存在并通过核验。
- 文章列表必须从同一内容集合生成，禁止同时维护硬编码列表与运行时 JSON 两套展示源。

### 8.3 数据流与人工边界

~~~mermaid
flowchart LR
  A[正式行情与飞书原始记录] --> B[只读事实分析]
  B --> C[判断、点评与感悟草案]
  C --> D{三段均已人工确认?}
  D -- 否 --> C
  D -- 是 --> E[一次性回填飞书]
  E --> F[生成并核验海报]
  F --> G[人工编辑网站公开版 MDX]
  G --> H{元数据、正文、海报与移动端通过?}
  H -- 否 --> G
  H -- 是 --> I[本地或封闭预览]
  I --> J[后续事实出现]
  J --> K[人工追加校准记录]
  K --> I
~~~

六周内不改造这条链路为自动发布。未来自动化可以读取已确认终稿、规范化数据、生成网站和海报草稿、检查缺项、渲染预览和提醒校准；不得选择交易标的、生成买卖动作、自动发布主观判断、覆盖原判断或跳过人工确认。

### 8.4 数据新鲜度与异常

- data_as_of 与内容日期相差 0—1 天：正常。
- 相差 2—3 天：显示“非当日数据”，正文说明用途。
- 超过 3 天：标记“待更新”，不得进入当日核心数字或判断依据。
- 来源读取失败：保留上次值但默认隐藏，页面显示“数据不可用”，不能静默回退。
- 非严格 JSON：在采集边界统一转换为标准 JSON，并保留转换日志；内容层只接收标准值或 null。
- 多来源冲突：不自动平均；列出差异并由人工选定正式来源。
- 发布时限未达成：保留真实完成时间并记录原因，不回填虚假时间。

### 8.5 未来 ERP Agent 边界

输入只能是已发布复盘、正式 ERP/估值数据、内部质量规则和用户主动提供的研究草稿；输出只能是事实摘要、缺项提示、历史相似状态、证伪条件建议和校准提醒。界面固定显示数据日期和“研究辅助，不构成投资建议”。禁止连接券商、读取持仓后给个性化动作、自动下单或以“策略胜率”做收益承诺。

## 9. 六周建设路线（约 180 小时）

六周建设按每周 30 小时的基准排期，总投入约 180 小时。建设期间从第 1 周开始持续完成真实复盘，网站未完成前先保留确认终稿，待内容集合可用后补录。

| 周次 | 主要工作 | 可验收产物 | 完成标准 | 落后时削减 |
|---|---|---|---|---|
| 第1周 | 冻结编辑规范、内容模型、页面结构；筛选历史文章；建立完成时间记录 | 日/周编辑规范、内容字段、历史候选清单、当周新复盘 | 3 篇历史日复盘和 1 篇周复盘可按新结构编辑；每个交易日开始记录完成时间 | 不做命名、Logo、外部测试和代码扩展 |
| 第2周 | 首页、日复盘、周复盘、产品化归档和文章页线框；设计 tokens 与移动优先原型 | 五类页面线框、桌面与 390px 原型 | 能从首页进入最新内容、精选复盘和年月归档；文章元数据、正文、海报与校准位置明确 | 不做动效和复杂数据图 |
| 第3周 | 建立 Astro 骨架、内容集合、日期路由、列表和上一篇/下一篇 | 本地可运行站点骨架 | daily/weekly schema 校验；列表只从内容集合生成；无硬编码双轨 | 不做搜索、统计、部署和自动化 |
| 第4周 | 完成文章阅读体验、海报嵌入、校准组件、产品化归档、移动端；迁移历史精选 | 8—12 篇历史日复盘、2—3 篇历史周复盘 | 所有文章有数据日期、来源、判断、边界和免责声明；归档具备最新、精选、年月和状态入口；移动端无横向滚动 | 优先减少装饰，不减少历史代表性 |
| 第5周 | 建立手动发布清单、数据异常状态、完成时间记录和封闭预览检查 | 可重复执行的当晚发布流程 | 从飞书确认到网站预览的步骤可重复；故意使用过期数据时页面正确标记 | 不接飞书写入、GitHub、分析和公开托管 |
| 第6周 | 连续自运行、修复流程摩擦、完整验收 | 封闭预览首版、内容与运行记录 | 满足下列六周完成条件；不以模拟用户反馈代替证据 | 先减渠道与视觉变化，不减内容质量和安全边界 |

### 9.1 六周完成条件

1. 在正常交易日历下至少积累 25 篇新日复盘；若六周实际 A 股交易日少于 25 天，则覆盖全部实际交易日。
2. 完成 6 篇新周复盘。
3. 完成 8—12 篇历史日复盘和 2—3 篇历史周复盘的编辑迁移。
4. 新日复盘记录真实完成时间；当晚 23:59 前进入网站预览，未达成时记录原因。
5. 每篇内容均区分事实、判断和待验证条件，包含数据日期、来源和免责声明。
6. 原判断不被覆盖；校准记录带日期追加。
7. 首页、最新内容、精选复盘、年月归档、校准更新、上一篇/下一篇和移动端阅读正常。
8. 海报完整显示，关键数字、颜色、字体、底部感悟和免责声明通过检查。
9. 六周只证明个人生产系统稳定，不宣称已完成市场验证，不伪造读者反馈。

### 9.2 六周运行判定

- **稳定**：日复盘当晚完成率不低于 90%，周复盘全部完成，周运营时间回落到约 20 小时，且没有来源或原判断被覆盖的严重错误。
- **需调整**：内容完成但经常超过 23:59，先减少小红书改写、视觉变化和站点小迭代。
- **不通过**：连续两周无法完成大部分日复盘、周复盘缺失、数据日期经常不明或原判断被改写。此时继续封闭运行，不申请公开发布。

## 10. 第 46—90 天公开验证路线

第 46 天不会自动公开。只有六周验收通过，且用户逐项授权预览托管、正式域名、分析工具和外部发布后，才进入公开验证。

### 10.1 三个验证循环

| 阶段 | 验证问题 | 观察信号 | 低于预期时先做什么 |
|---|---|---|---|
| 第46—60天 | 小红书海报能否把合适读者带到完整文章 | 海报到站访问、最新文章打开、归档进入 | 先改海报题眼、网站首屏和入口一致性，不增加栏目 |
| 第61—75天 | 读者是否愿意回来查看下一篇或旧判断 | 每周回访读者趋势、上一篇/下一篇使用、历史归档阅读 | 先强化更新时间、文章连续性和校准入口，不做账号系统 |
| 第76—90天 | 稳定内容是否产生真实的付费或工具需求 | 主动反馈、内容会员意向、对整理工具或 Agent 的具体问题 | 只记录和访谈，不立即收费或开发工具 |

### 10.2 指标原则

- **北极星**：每周回访读者趋势。
- **辅助指标**：小红书到站访问、最新文章阅读、归档进入、上一篇/下一篇使用、校准记录阅读。
- **内容运营指标**：日复盘当晚完成率、周复盘完成率、来源和日期完整率、校准追加率、周运营耗时。
- **不设固定人数门槛**：公开首个周期只看趋势、行为和真实反馈，不以早期流量作虚假成功或失败判断。
- **不使用虚荣指标决策**：曝光、点赞和粉丝数只能说明渠道触达，不能替代回访。

### 10.3 第 90 天决策

- 回访趋势持续改善且运营稳定：保持两个栏目，开始验证内容会员意愿。
- 有阅读但几乎没有回访：先改连续阅读、归档和校准叙事，不扩展工具。
- 小红书有曝光但到站弱：先调整海报摘要与网站文章的承接关系。
- 读者明确提出重复、具体的研究整理痛点：记录为未来工具需求，不提前进入 Agent 开发。
- 运营时间连续两周超过 20 小时：先减少渠道加工和站点迭代，不牺牲日/周复盘与来源核验。

## 11. 一年演进路线

| 阶段 | 进入条件 | 重点交付 | 决策原则 |
|---|---|---|---|
| 阶段1：0—3月，稳定输出 | 本蓝图获批并单独授权本地实现 | 封闭预览、25+ 新日复盘、6 篇周复盘、历史精选、公开验证准备 | 个人生产系统不稳定则继续封闭，不做商业化 |
| 阶段2：4—6月，建立读者关系 | 获得公开授权且网站能稳定更新 | 小红书引流、日期归档、校准记录、回访趋势与真实反馈 | 不用粉丝数代替回访；没有回访就先改内容承诺 |
| 阶段3：7—9月，内容会员实验 | 回访趋势稳定，读者主动表达持续内容需求 | 小规模支持型会员说明、月度或季度校准报告、主理人信件、结构化历史索引 | 先验证愿意为什么付费；完整免费日/周复盘不能突然被锁住 |

一年路线不是功能日历。每个阶段只有在前一阶段的真实证据成立后才进入；不得为了按时做 Agent 而跳过内容和需求验证。

## 12. 商业化实验

### 12.1 顺序

1. **六周封闭期**：不售卖，只建立稳定内容资产。
2. **第46—90天**：公开后观察回访和主动需求，不设置付费墙。
3. **第一商业假设**：内容会员，包括持续周复盘、阶段性专题或结构化历史档案。
4. **第二商业假设**：研究整理工具或 Agent，仅在重复、具体的效率痛点出现后验证。

### 12.2 Monevator 式会员原则

未来会员首先是一种支持长期独立创作的关系产品，而不是信息优势承诺。可以验证的增量价值包括：

- 月度或季度校准报告。
- 历史判断的结构化索引和主题整理。
- 独立周复盘的研究附件。
- 主理人月度信件或阶段性幕后说明。
- 对独立内容持续运营的支持身份。

会员上线必须同时满足：免费内容已稳定运行、归档被持续使用、出现主动支持或付费意愿、主理人能在 20 小时周预算内交付。会员不能获得实时买卖提醒、隐藏仓位、更激进的操作结论或收益承诺。

如果未来引入广告或联盟推荐，必须单独授权并公开利益关系；不得为了联盟转化改变复盘判断。首期和第 46—90 天均不引入。

### 12.3 可验证方向

| 优先级 | 假设 | 最小验证方式 | 进入条件 | 停止条件 |
|---|---|---|---|---|
| 1 | 读者愿意为持续、稳定、可回看的内容关系付费 | 访谈、意向登记或小规模会员说明页 | 回访趋势稳定且出现主动询问 | 只有点赞，没有持续阅读或付费理由 |
| 2 | 历史校准档案比单篇观点更有长期价值 | 观察归档和校准记录阅读，访谈使用场景 | 归档被持续使用 | 读者只消费最新海报，不使用历史内容 |
| 3 | 研究整理工具能减少重复工作 | 人工演示或无交易动作的轻原型 | 多人提出相同输入、输出和频率需求 | 需求集中在荐股、仓位或收益承诺 |
| 4 | ERP Agent 可作为研究辅助 | 邀请制原型，展示数据日期、来源和历史对照 | 内容与数据链稳定、审计清楚 | 被当作买卖信号或要求接入交易执行 |

不能收费包装：具体买卖点、收益承诺、代客操作、持仓建议或未取得资质的个性化顾问服务。

## 13. 指标与决策机制

### 13.1 指标树

- **封闭期核心指标**：真实交易日复盘当晚完成率。
- **公开期北极星**：每周回访读者趋势。
- **内容质量**：事实/判断/边界完整率、来源与日期完整率、原判断保留率、到期校准率。
- **阅读行为**：最新文章打开、上一篇/下一篇使用、归档进入、校准记录阅读。
- **渠道质量**：小红书海报到站访问与后续回访，不用曝光量单独排序。
- **运营健康**：每周总耗时、延迟发布次数、数据异常次数和修正耗时。

### 13.2 继续、调整、停止规则

- **继续**：内容按时、质量边界完整、周耗时可控，且公开后回访趋势没有持续恶化。
- **调整**：文章有人读但没有回访，先改更新时间承诺、系列连续性、归档和校准入口。
- **调整**：小红书有曝光但到站弱，先改题眼、副标题和网站落地内容的一致性。
- **调整**：周运营连续两周超过 20 小时，先减渠道加工、视觉变化和功能开发。
- **停止扩张**：个人输出尚不稳定时，不增加栏目、付费、社区或 Agent。
- **立即收缩**：内容被持续误解为荐股、出现隐私泄露或主观判断被自动覆盖。

## 14. 风险与控制

| 风险 | 预警信号 | 预防 | 触发后的动作 |
|---|---|---|---|
| 个人运营过载 | 连续两周超过 20 小时、日复盘延迟 | 两个栏目、固定文章结构、固定海报版式 | 先减渠道与小迭代，不减来源和复盘质量 |
| 为日更牺牲质量 | 事实与判断混淆、来源缺失 | 发布清单和 preview 门槛 | 当日标记延迟，不发布未经确认的主观判断 |
| 事后改写 | 原判断被新结果替换 | 校准只追加的数据结构 | 恢复原文，公开修正原因并检查发布流程 |
| 数据陈旧 | 核心数据超过 3 天仍展示 | data_as_of 必填和过期状态 | 隐藏旧值，显示待更新 |
| 权威或跟单误解 | 读者追问买卖点、仓位、收益 | 平视身份、观察条件、固定免责声明 | 重写题眼和 CTA，删除动作化表达 |
| 隐私泄露 | 文章或截图出现账户、金额、持仓 | 公开版人工精编，不直接发布飞书全文 | 立即下线相关内容，修复后再恢复 |
| 平台依赖 | 小红书贡献绝大多数访问 | 网站为正式公开档案，URL 稳定 | 减少平台专属格式投入，保留内容母稿 |
| 双源不一致 | 飞书判断与网站表述冲突 | 飞书确认终稿为准，网站只做公开编辑 | 暂停发布，对照确认版本重新编辑 |
| 自动化越权 | 脚本跳过确认或覆盖判断 | 六周不自动发布，后续权限分级 | 关闭相关任务，恢复人工闸门 |
| 范围膨胀 | 出现方法页、账号、社区、Agent需求 | 首期不做清单、周度范围审计 | 新增项必须替换同等工时任务，不能叠加 |

## 16. 关键假设与后续研究

### 16.1 当前假设

1. 主理人稳定、透明的长期复盘比先提供教学工具更能建立初期可信度。
2. 精编公开版比直接展示飞书完整原稿更适合长期阅读。
3. 每日和每周两个栏目足以支撑首期内容产品，不需要方法、工具或研究看板。
4. 原判断与后续校准同页呈现，能建立比只展示最新观点更强的信任。
5. 小红书竖版海报能成为公开阶段最合适的发现入口。
6. 六周建设阶段可投入约 180 小时，稳定运营必须回到约 20 小时/周。
7. “心猿意马的羊”作为现有网名适合跨网站与平台统一使用；正式公开前仍需检查账号与域名一致性。
8. Monevator 式“完整免费内容 + 长期归档 + 支持型会员”比早期付费墙更符合本项目的平视关系。

### 16.2 公开后需要回答的问题

- 哪类标题最能让合适读者从海报进入完整文章？
- 读者更常回看新的日复盘、周复盘，还是旧判断的校准？
- 精编长文的哪些部分被真正阅读，哪些内容只是重复信息？
- 固定更新时间是否能形成回访习惯？
- 什么表达会让读者误认为这是荐股或老师带盘？
- 读者愿意为什么付费：稳定内容、专题档案、历史校准，还是研究整理工具？

这些问题只能通过真实行为、自愿反馈和后续访谈回答；六周封闭期不招募外部测试者，也不编造答案。

## 17. 90 天内明确不做

- 对外教学方法、提供读者填写表格或把练习完成作为核心指标。
- ERP Agent、自动交易、持仓连接或个性化策略。
- 用户账号、社区 feed、排行榜、评论和私信。
- 付费墙、内容收费、订阅制工具和正式顾问服务。
- 广告、联盟推荐、会员账户和会员专属评论。
- 实时行情大屏、复杂图表终端和全市场扫描器。
- 多作者 CMS、原生 App、国际化和深度 SEO 工程。
- 全自动外部发布；所有主观内容必须人工确认。
- 公开飞书原始全文、个人仓位、具体买卖动作和账户信息。
- 为追求日更而降低来源、判断边界和校准质量。
- 未经单独授权部署公开网站、接入统计或发布外部渠道。
