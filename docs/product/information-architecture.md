# 信息架构

状态：2026-08-25 首页定稿版（固定文案以 `docs/content/site-copy.md` 为准）

## 1. 顶层导航

桌面端固定为：

`首页 / 每日复盘 / 每周复盘 / 归档 / 关于`

移动端分两行显示署名和完整五项导航，不使用横向滚动菜单。

## 2. 页面职责

| 页面 | 回答的问题 | 必须展示 | 主要动作 |
|---|---|---|---|
| 首页 | 作者是谁、这里长期提供什么 | 身份与承诺（hero 纯文案）、全部复盘统一列表、ERP 策略／行业启动／估值罗盘工具入口、复盘原则、首页底部免责声明 | 阅读复盘或打开研究工具 |
| 每日复盘 | 每个交易日怎样从事实走到判断 | 带左侧封面的倒序列表、摘要、数据日期、判断状态、校准状态 | 打开当天文章 |
| 每周复盘 | 高周期市场结构怎样变化 | 带左侧封面的倒序周报、核心判断、估值日期、下周观察条件 | 阅读最新周报 |
| 归档 | 旧判断后来怎样，哪些文章值得重读 | 最新更新、手工精选、年月索引、类型和校准状态 | 浏览历史与校准 |
| 关于 | 为什么值得长期跟踪，边界是什么 | 作者身份、编辑原则、来源政策、修正政策、三项研究工具入口 | 理解写作规则或打开研究工具 |
| 研究笔记 | 外部观点怎样被理解和验证 | 来源署名、原始链接、作者理解、数据日期 | 阅读辅助研究记录 |
| 文章页 | 当时事实、判断、边界及后来校准是什么 | 元数据、正文、海报、来源、免责声明、校准、上一篇/下一篇 | 连续阅读或回到归档 |
| 海报版 | 读者怎样最快掌握一篇复盘 | 完整正式海报、文章版切换、上一篇/下一篇 | 查看原图或切回文章版 |

## 3. 首页顺序

固定自上而下，任何区块不得擅自增删：

1. **hero（首屏）**：kicker（`MARKET REVIEW · OBSERVE / JUDGE / CALIBRATE`）、大标题、副标题。**纯文案，无按钮、无提示条、无免责标签**。
2. **全部复盘**：日复盘与周复盘**统一单一列表**，按 `date` 倒序混合排列，不设"最新/最近"分区。每项为紧凑卡片（类型 · 日期 · 标题 · 摘要 · 阅读全文）。
3. **研究工具**：ERP 策略、行业启动和 估值罗盘三个独立外部入口；仅提供研究证据，不自动改写复盘判断。
4. **复盘原则**：事实／判断／边界／校准四项固定说明。
5. **免责声明**：首页最底部 `#disclaimer`，固定文本见 `docs/content/site-copy.md` 第 7 节，不设独立免责声明页面。
6. **页脚**：站名与副句、固定三项链接（研究笔记／研究工具／免责声明）。

首屏不放新闻简报、老师观点、搜索框、订阅假按钮、标签云或数据大屏。研究笔记只有在存在合格公开内容时才作为二级入口露出。

首页、每日、每周和研究笔记列表使用统一文章条目：桌面端左侧为约 180×120 的 3:2 封面，移动端约 104×70。没有独立图片时显示自动排版卡片；日期归档仍使用紧凑文字索引。

## 4. 归档作为产品

吸收 Monevator 的长期档案和作者—读者关系原则，但不复制其视觉、广告、评论或会员功能：

- **最新更新**把新文章和旧文章校准放在同一时间线，避免校准被埋没。
- **精选复盘**由作者手工选择判断链完整、后续校准有价值的文章，而不是只选结果最好的一篇。
- **年月索引**从单一内容集合自动生成，日、周可筛选但不拆成两套数据。
- **状态识别**在列表上直接显示待验证、部分支持、被否定或已支持。
- **连续阅读**提供上一篇、下一篇，以及同周或相关校准入口。
- **稳定链接**发布后不随标题变化。

首期不做全文搜索、复杂标签、排行、推荐算法、收藏和评论。内容数量证明年月索引不够用后再评估搜索。

## 5. 文章页结构

```text
作者 / 内容类型 / 日期 / 数据截止 / 来源数量 / 判断状态 / 最近校准
标题：事实 / 当前判断
摘要与保留条件
正文：事实 → 结构 → 判断 → 边界 → 点评 → 感悟
完整海报
来源与免责声明
按日期追加的校准记录
上一篇 / 下一篇 / 返回归档
```

校准记录必须视觉上与原判断分开，并显示追加日期；不能把新结果回写进旧正文。

## 6. URL 与排序

- 日复盘：`/daily/YYYY-MM-DD/`
- 周复盘：`/weekly/YYYY-Www/`
- 日复盘海报版：`/daily/YYYY-MM-DD/poster/`
- 周复盘海报版：`/weekly/YYYY-Www/poster/`
- 归档：`/archive/`，年月入口使用 `/archive/YYYY/MM/`
- 关于：`/about/`
- 研究笔记：`/research/` 与 `/research/<slug>/`

列表默认按 `date` 倒序；“最近更新”按 `updated_at ?? published_at ?? completed_at` 倒序。上一篇/下一篇按内容日期计算，不按标题或文件名猜测。

## 7. 移动端优先级

390px 下使用单列、20px 页面边距、正文不小于 16px：

- 首屏先显示署名、承诺和最新复盘，再显示其他内容。
- 关键事实表转为“指标—数值—含义”的纵向行。
- 海报保持完整比例，可点开原图，不裁掉底部免责声明。
- 列表封面保持在左侧并压缩摘要；极窄屏才允许封面移动到标题上方。
- 长来源和 URL 允许换行，页面不得产生横向滚动。
- 涨跌与校准状态同时使用文字或图标，不能只靠红绿颜色。

## 8. 首期边界

本信息架构不包含方法教学、读者填写、账号、CMS、数据库、社区、站内实时行情终端、付费墙、ERP Agent、评论、广告或联盟推荐。ERP 策略、行业启动和 估值罗盘仅以独立外部研究工具链接接入，不复制其生产数据，也不包装成自动买卖信号。
