# 每日复盘笔记本海报

把飞书或等价母稿保留为完整思考记录，把海报制作成可快速阅读的结论页。使用 Skill 自带模板、底图和脚本，不寻找旧海报作为模板。

## 必读资源

1. 每次完整读取 [references/review-contract.md](references/review-contract.md)，执行确认门槛、内容映射和视觉规则。
2. 需要生成正式交接包时，再读取 [references/handoff-contract.md](references/handoff-contract.md)。
3. 使用 [assets/poster-input-template.json](assets/poster-input-template.json) 建立当日结构化输入。
4. 使用 [assets/notebook-poster-template.html](assets/notebook-poster-template.html) 和画布库 `notebook-paper` 包（`D:\CC\shared\assets\canvases\notebook-paper\`，背景 `background.png`）；不要从历史输出反推模板；画布库规范见 [../../docs/operations/canvas-library.md](../../docs/operations/canvas-library.md)。**换用其他 pack 做背景时，背景文件名一律取该 pack `canvas.json` 的 `file` 字段，不要凭目录里的文件名猜**——一个 pack 里可能同时有正式版与旧版 PNG（2026-09-15：`snowball-editorial-3x4/` 里 `background-v1.png` 是 v1.0 无 logo 版，登记的 `background-v1-logo-v1.png` 才是 v1.1.0 带 logo 版）。构建后用 `notebook-background.png` 的 SHA-256 与画布库登记值比对兜底（逐字节拷贝，应完全一致）。
5. 周复盘或母稿含「估值」栏时，读取 [../../docs/operations/valuation-data.md](../../docs/operations/valuation-data.md) 执行估值数据自动回填（数据源、口径、回填与复核见该契约）。
6. 生成纪律总纲（确认门槛、题眼措辞、QA 探针、备份纪律）：读取 [../../docs/operations/poster-production-rules.md](../../docs/operations/poster-production-rules.md)。
7. 小红书/私域引流版（3:4 1080×1440）由独立 Skill [../teaser-poster/SKILL.md](../teaser-poster/SKILL.md) 负责；本 Skill 只负责复盘海报（1080×2000）。

## 标准流程

1. **发现母稿**：按编辑时间确认正确日期；分开识别事实、作者判断、模板提示、图片和缺失项。
2. **分析事实**：形成“现象 → 结构 → 判断 → 条件”，核对量能、广度、中位数、日内节奏、风格、均线和外围映射。
3. **逐段确认**：依次确认今日判断、收盘点评和个人感悟。三段未全部确认时，只能制作明确标记的预览，不得回填或交接为 `ready`。
4. **回填并复核**：使用当前工作台可用的飞书或文档工具，一次性回填三段；重新读取确认成功且未覆盖原始记录。工具不可用时保留 `incomplete`，不要假装已回填。
5. **估值数据自动回填（周复盘或含估值栏的母稿）**：按 `docs/operations/valuation-data.md` 读取本地 `D:\CC\pe\data\` JSON（宽基 PE / 国债 / 波动率 / 换手集中度 / 红利股息率）与线上 ERP（`https://erp.fupanxinyuan.com/data/merged_signal.json`，**2026-09-22 起；旧 `index-compare-analysis.vercel.app` 国内 DNS 已污染不可达**）。只填事实数字并带数据日期，不生成“偏贵 / 便宜”判断；用 lark-cli `block_replace` 逐个回填并重新 fetch 核验。数据断档或工具不可用时保留 `incomplete`，不伪造不补造。
6. **映射海报**：复制 `poster-input-template.json`，只填已确认文字和可核验数字。保持两条事实、四个指标、三栏结构、四项判断、三项验证条件、总结和感悟。
   - **`type` 必填语义**（2026-09-12 新增）：`daily` 或 `weekly`，决定三处类型字样——页脚「日复盘/周复盘笔记本海报」、网页标题「A股日复盘/周复盘｜笔记本海报」、第 1 节小标题「今天/本周发生了什么？」。**周稿务必显式填 `weekly`**；缺省 `daily`（旧 JSON 不带 `type` 仍按日稿渲染，向后兼容）。此前该字样写死在模板里，周稿成品被误标成「日复盘」（W36 受影响）。
   - **各栏行数上限（写 JSON 时按此控制，2026-09-15 补全）**：标题第二行 **≤10 字**（`.topline` 的 `1fr` 列宽 = 715−116−150−2×15 = **419px**，h1 38px + letter-spacing 2px = 每字 40px；第 11 字折到第 3 行、白吃 47.5px）｜判断栏每格 body ≤3 行、标题 ≤17 字｜总结 ≤2 行｜三栏每栏每项 ≤5 行（`li` 折行）｜两条事实各 ≤2–3 行｜三项验证 body ≤2 行｜金句控制在 1–2 行。
   - **用户自拟题眼超 10 字时的处理（2026-09-15 用户确认的处置）**：压标题（删虚词、保留实义），**删掉的词必须保留在事实段与判断栏的完整表述里**，并在交付说明与 handoff 里明确讲清楚压了什么、为什么压——用户对这个取舍有知情权，压完再让他拍板。
7. **构建 HTML**：运行：

   ```text
   python scripts/build_poster.py <input.json> --output-dir <目录> --stem poster-YYYYMMDD
   ```

   **深底画布加 `--theme dark`**（如「星云随笔」深靛蓝底）：脚本把模板 CSS 变量翻成浅色系（`--ink #F5EEDD` / `--red #F2DDB4` / `--green #A8D8C4` / `--muted #C9C2E8` / `--rule #8D84B0`，body 底色 `#202C50`），沿用 2026-09-09 星云版定版配色。**不要手工改生成的 HTML**——替换目标未命中时脚本会报错而非静默跳过。

   **换背景与重跑的两个坑（2026-09-18 实测）**：① 指定 `--background <图>` 时脚本会把背景复制为 `<输出目录>/notebook-background.png`，第二次运行起会因目标已存在而报 `FileExistsError`，需加 `--force`；② 若该目标文件**正被其他程序占用**（Windows 文件锁），`--force` 也绕不过——`shutil.copy2` 抛 `PermissionError: [WinError 32] 另一个程序正在使用此文件`，且此时 HTML 已写入、只有背景拷贝失败，容易误判为构建失败。**处置：先删掉输出目录里的 `notebook-background.png` 再重跑**（`--background` 指回画布库原图即可）。

8. **渲染 PNG**：在安装 Chrome、Chromium 或 Edge 的环境运行：

   ```text
   python scripts/render_poster.py <poster.html> <poster.png>
   ```

   脚本必须验证 PNG 为 `1080×2000`。没有兼容浏览器时交付 HTML 并明确报告缺失依赖，不改用不可核验截图冒充完成。

9. **完整视觉 QA**：先跑内容高度探针（程序化，不依赖模型看图）：

   ```text
   python scripts/render_poster.py <poster.html> <poster.png> --probe [--probe-bg dark]
   ```

   （`--probe-bg dark` 只在深底画布 / `--theme dark` 时加，浅底画布用默认的 `light`。）
   **PNG 位置参数是必填的**（argparse 报 `required: png` 就是漏了它）。
   **`--probe` 是短路模式：它只做探针渲染，绝不写出最终 `<poster.png>`（脚本 `if a.probe: return run_probe(a)`）——这是 2026-09-18 踩到的坑**：改完文案后若只跑 `--probe`，交付的成品图会**静默停留在旧版**，而 SHA/mtime 看起来「没变」极易被当成「没改成功」或忽略掉。纪律：**每次改完输入 JSON，顺序是 ① build → ② 不带 `--probe` 渲染正式图 → ③ 再跑 `--probe` 复核**；交付前必须用 `mtime` / SHA 确认 PNG 确实刷新过（W38 实例：旧图 `6a9c7b25…` 挂了两轮，正式出图后变为 `83684381…`）。

   退出码 `0` 表示未超出 2000px 画布，输出底部余量；建议留 20-40px 视觉留白。溢出时**压缩输入 JSON 文案**（判断栏每栏 body 控制在 3 行内、总结控制在 2 行内），不要改模板 CSS。随后查看最终 PNG（而不是只看空白底图），确认文字无溢出、底部未裁切、装饰不遮正文、感悟和页脚。

   **成品图一致性核验（防「陈旧交付图」，2026-09-18 新增）**：探针报的是**你刚改完的那份 HTML**，不等于磁盘上那张 `poster.png`。交付前跑一次底图差分核验，拿独立证据确认成品图确实重出过：

   ```text
   python scripts/verify_poster_png.py <poster.png> <包内 notebook-background.png> --expect-margin <探针报的余量>
   ```

   脚本按 CSS `center/cover` 复现底图、与原图逐行差分，得到内容纵向范围与底部余量，并与探针报数交叉验证（差 >12px 即判 FAIL 并提示「`--probe` 不写成品图，请重跑」）。W38 实测：探针 39px / 脚本 41px（差 2px）、内容末行 y=1958、其余行为 0 → PASS。

   **余量不达标时，先定位再压——不要盲压文案（2026-09-15 建立，2026-09-17 脚本化）**：

   ```text
   python scripts/measure_blocks.py <poster.html>
   ```

   探针只报一个总数，不告诉你谁在吃高度。本脚本在临时副本里注入测量脚本、用 headless Chrome 求出各块实际行数（标题 / 导语 / 两条事实 / 三栏每格含是否折行 / 判断栏 / 总结 / 金句 / 三项验证），并附三栏逐项 rect 明细。一次就能找到那一个真正超限的块。要点：`getBoundingClientRect()` 返回的是**含 `.sheet` scale(1.18) 的值，脚本已按 1.18 还原**；三栏 rect 里**同一 y 属同一行，出现第二个 y 即折行**（0917 实例：`领先指数` 值超列内可用宽 192px，末字成孤儿，压成「差约 0.5」后 12 格全部单行）。属诊断工具，不产出交付物。

   **压完必须重测行数，不能凭字数推断（2026-09-18 实测）**：导语从 125 字压到 100 字仍是 4 行，压到 88 字才落到 3 行——行数由换行临界决定，**字数减少不等于减行**；同理某栏的值「看起来短了一点」也可能仍在折行。**每次改完输入 JSON，都要用本脚本复核行数并重跑高度探针**，否则会出现「改了文案、底部余量却一动没动」的假象（0918 首轮即如此：同轮改了两处，探针报数与改前完全相同，误以为 HTML 没更新）。

   **余量偏宽（>40px）也是问题**：说明信息量不够或某处白占高。可在**不增行的前提下把信息量白捡回来**（0915 W37 实例、0917 实例：把整篇点评里唯一没进海报的主题补进 facts 第 3 行），或把金句拆成两行增强分量——**不要为凑高度注水，也不要用空行撑**。

   **余量偏窄（<20px）时：删句，不是压字；删最冗余的块（2026-09-18 建立）**。W38 周稿余量只有 +5px（等于页脚贴着画布下沿），要抬进 20–40px 就得**回收整整一行**——而「压字数」在临界点前完全不减行（见上条）。正确做法是找**全稿最冗余的那一句**删掉：W38 导语里的广度句（`中证全指 +1.61%、平均股价 +5.1% 由负转正，但全A中位仅 +0.74% 仍显弱`）与 facts[1]、三栏第 2 列、判断栏第 2 格、总结**四处重复**，删掉它导语 3 行→2 行，余量 +5px→**+39px**。反之，facts[0] 里的「历史最大 8.05」「跳空上到 5 日周线上方」是全稿唯一出处，**绝不能为了腾高度删这种唯一信息源**。

   **快速找「N 行区间的最长文案」：注入式行数试验（2026-09-18 建立，省掉反复重建）**。不要一轮一轮「改 JSON → 重建 → 渲染 → 探针」（一轮半分钟且改坏要回滚）。直接**复制已生成的 `poster.html`**，用正则替换目标块的内容，逐个喂给 `measure_blocks.py` 就能拿到行数，几秒一个候选：

   ```python
   # 复制 poster.html → 正则替换 <p class="lead">(.*?)</p> → 跑 measure_blocks.py → 读 "lead N"
   m = re.search(r'(<p class="lead">)(.*?)(</p>)', html, re.S)
   p.write_text(html[:m.start(2)] + 候选文案 + html[m.end(2):], encoding="utf-8")
   ```

   确认胜出文案后再**只写回输入 JSON 重建一次**。实测 W38 导语：68 字 →2 行，72–74 字 →2 行，**75 字 →3 行**（拉丁数字/百分号比汉字窄，**可用宽度不等于字数，必须实测**）。

   **金句含 `<br>` 时行数会被多算 1（2026-09-18 修）**：`<br>` 会在行尾产生一个 width=0 的空 rect，双行金句被 `lines()` 数成 3 行、看起来像超了「金句 1–2 行」上限。脚本 `rects()` 已过滤零宽 rect。**看到金句行数「比肉眼多 1」，先确认金句是否带 `<br>`，不要急着改文案。**

   **浅色文字海报必须加 `--probe-bg dark`**（即配 `--theme dark` 的深底画布）：探针改在黑底扫亮像素；不指定时默认白底扫暗像素，浅色字会漏检导致假通过。

   **底图对比度探针（用非 `notebook-paper` 背景时必做，2026-09-14 新增）**：内容高度探针只查「有没有溢出」，查不出「看不看得清」。3:4 画布（1086×1448）cover 到 1080×2000 会放大 1.381×（裁左右各 210px），**其设计安全区通常只到画布 y≈1492**，而模板内容一直排到 y1960——页脚（来源 + 免责声明，10px 小字）容易落进底图暗部而不可读（0914 雾海微明实测仅 2.01:1）。

   ```text
   python scripts/probe_background_contrast.py <background.png> [--dark]
   ```

   脚本按 CSS `center/cover` 逻辑取背景并缩放到 1080×2000，按模板纵向分段，算出各前景色（模板 CSS 变量的 WCAG 等效灰度）对段内背景均值的对比度。退出码 `0` = 达标（可能附「边缘」提示，达阈值 90%），`1` = 有段落不足。

   阈值：正文与强调 4.5:1（≥24px 大字 3:1）；页脚 3.5:1（辅助信息，本 Skill 工程口径，低于 AA 严格值，已在脚本中显式记录）。不达标时只有两条路，**都需用户确认，不得擅自执行**：① 底图下段渐变提亮（画布 y1500 起与纯白 alpha 0→0.72 线性混合，会洗淡底图）；② 模板 `footer` 加衬底（不动底图、跨背景通用）。**用户选择保留原底图时，须在 handoff「未完成事项」留档该遗留。**

   **修法 ② 已于 2026-09-22 实装（用户拍板「页脚2」）**：模板 `:root` 新增 `--footer-bg`，`footer` 改为 `background:var(--footer-bg);border-radius:8px;margin:11px -12px 0;padding:7px 12px 6px`。**衬底必须随主题取色**——paper 暖白 `rgba(255,252,245,.78)`、dark 深靛 `rgba(32,44,80,.72)`（`build_poster.py` 的 `THEME_PAPER` 已同步）。别只做「浅色衬底」：深底主题（星云等）是**浅色字**，压在浅衬底上会被反噬。三条连带纪律：

   1. **加了衬底，重跑本探针必须带 `--footer-scrim`**（浅底 `"255,252,245,0.78"`／深底 `"32,44,80,0.72"`），脚本会把衬底按 alpha 合成到页脚段亮度再计算；不带就按「无衬底」**误报 NOT PASS**。
   2. **动模板 `:root` 必须同步改 `build_poster.py` 的 `THEME_PAPER` 键串**——它是**整串匹配**，不同步会在 `--theme dark` 时直接报「替换目标未命中」。
   3. **衬底会多吃约 6px 高度**（footer padding 由 8px 变 7+6px，净 +5px 未缩放 ≈ 6px 缩放后），排版预算按 +6px 预扣；水平包围盒由 x[131,976] 扩到 **x[118,990]**（左右各外扩 12px 未缩放），仍在 1080 画布内。

   实测存档（页脚对比度 / `--dark` 档）：**笔记本纸 4.10｜橘猫彩蛋 4.32｜星云随笔 5.50｜雾海微明 2.01 → 加衬底 5.58**。反直觉但成立：**深底画布页脚本来就最清晰**（星云深靛蓝底 + 浅色页脚字衬得开），真正需要衬底的是**浅底画布**（页脚落进底图下段暗部）。加衬底前星云另有两个「边缘项」（三栏强调 4.31、判断栏强调 4.44，达阈值 96%/99%）属达标但接近线，底图换版需重测。
10. **局部修订**：只修改用户指出的对象。调整钢笔时只移动钢笔及其阴影，保持纸张、线圈、木桌、绿植、书本、光线、比例和角度不变；重新构建并检查完整成品。
11. **视觉确认与清理**：用户确认前用 `-vN` 保存候选；确认后只保留被选中的 HTML、PNG、底图和必要交接证据，删除被拒绝的预览与临时截图。
12. **正式交接**：按 `handoff-contract.md` 生成稳定文件名和 `handoff.md`。网站、部署、策略与生产数据不在本 Skill 的写入范围。

## 不可变规则

- 固定画布 `1080×2000`；HTML 是可编辑源，PNG 是渲染结果。
- 每个数字都说明对象、单位、比较基准和含义；最多四组。
- 不把“修复”升级为“反转”，不把“待验证”改成“已确认”。
- 不公开持仓、仓位、账户金额、收益截图或具体买卖动作。
- 不运行或修改 ERP、PE、相对比价策略及交易执行。
- 不依赖 Codex、某个浏览器插件或专属工作区绝对路径；使用 Skill 相对资源和通用 Python/浏览器接口。
